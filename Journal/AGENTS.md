## 2. Paper Summary (for AI context)

### What the paper does
The paper presents a **proof-of-concept digital twin** for real-time Cold-Leg Loss-of-Coolant Accident (LOCA) screening in the Westinghouse AP1000 pressurized-water reactor (PWR). It replaces slow ANSYS Fluent CFD runs (1-4 h/scenario) with three neural operator surrogates that predict four coupled thermohydraulic fields (pressure p, velocity magnitude |v|, turbulence kinetic energy k, temperature T) over a 25,000-node mesh in < 20 ms (approx. 180,000x speedup).

### Five-stage pipeline
1. **Data Generation** — ANSYS Fluent (production) or physics-consistent mock generator (development). Parameter space: v in [4-6 m/s], b in [0-10%], T in [290-320 C]. 2,000 samples (70/15/15 split).
2. **Preprocessing** — CSV to HDF5; per-field MinMaxScaler; branch tensor U, trunk Y, target S.
3. **Neural Operator Training** — Three architectures (see Section 3 below).
4. **LOCA Classifier** — Gradient Boosting Classifier on real NPPAD data (302 Normal + 45,176 LOCA rows) + 3,800 synthetic transitional rows.
5. **Inference** — normalize -> neural operator -> denormalize -> feature extraction -> NPPAD mapping (blended severity eta_eff = 0.8*eta_input + 0.2*eta_CFD) -> GBC -> P(LOCA).

### Three neural operator architectures

| Architecture | Params | Key idea | Loss |
|---|---|---|---|
| DeepONetFourier (Tier 1) | ~1.45 M | Branch-trunk + random Fourier features (sigma=10, m=256) + adaptive GELU + Sobolev loss (beta=0.1) + divergence-free penalty (lambda=0.01) | Sobolev + Div |
| Transolver++ (Tier 2) | ~106 K | Mesh tokenized to M=64 tokens via soft-assignment; 4x 8-head self-attention blocks; O(M^2) complexity | MSE only |
| Clifford Operator (Tier 2) | ~1,796 | Cl(3,0) geometric algebra; grade-structured multivectors encode scalars (p, T) and vectors (v); rotational equivariance by construction | MSE only |

### Key results (synthetic benchmark)
- DeepONetFourier: val loss 9.11e-4, R2 > 0.90 all fields (note: stronger loss than other two)
- Transolver++: R2 > 0.88; Clifford: R2 > 0.85
- LOCA classifier: ROC-AUC > 0.95, recall > 0.92, F1 > 0.90 (substantially driven by input break-size)
- End-to-end latency: < 20 ms (GPU, NVIDIA RTX 4060)

## 3. Writing Style Guide

The paper follows IEEE Transactions on Reliability style. When generating or editing text, adhere to:

### Language & tone
- Formal academic prose; third-person except in explicit "we" contribution statements.
- Precise and hedged when appropriate: use "under the synthetic benchmark", "preliminary", "proof-of-concept", "to the best of our knowledge" where the paper already uses them.
- **Strategic Framing & Paper Strength**: Always frame facts, figures, and results in a manner that strengthens the paper's narrative. Avoid self-sabotaging comparisons. If a simpler baseline appears to have higher raw metrics on a simpler objective (e.g. MSE), emphasize the parameter efficiency and harder physical constraints of the proposed architecture. Never present data in a way that undermines the paper's core contributions.
- Never overstate validated capability — always qualify results with benchmark scope.
- Consistent British or American English within a section.

### Structure conventions
- Section headings in ALL CAPS Roman numerals (IEEE style): e.g. "II. R ELATED W ORK"
- Subsections as "A. Subsection Name", sub-subsections "1) Sub-subsection Name:"
- Figure captions: sentence-case, start with "Fig. N:"
- Table captions: above the table, sentence-case.
- Equations numbered with round brackets right-aligned: (1), (2), etc.
- "[Input/confirmation required from the students: ...]" is the paper's placeholder convention.

### Mathematical notation
- Vectors bold-lower: u, v; matrices bold-upper: B; scalars italic: v, b, T
- Neural operator: G_theta; branch: B; trunk: T; basis dimension: p = 256
- Field output: s-hat(y) = [p-hat, |v-hat|, k-hat, T-hat]^T in R^4
- Loss weights: alpha = 1.0 (MSE), beta = 0.1 (Sobolev), lambda = 0.01 (divergence)
- Blended severity: eta_eff = 0.8*eta_input + 0.2*eta_CFD
- Clifford algebra: Cl(3,0); grade-0 = scalars, grade-1 = vectors, grade-2 = bivectors, grade-3 = trivectors

### Citation style
IEEE numeric: [1], [2], etc. Bracketed at end of clause before period.

## 5. AI Assistant Workflow for Edit Requests

When a professor/reviewer paragraph is given as input:

1. **Understand the request** — parse what is being asked: new text, clarification, literature addition, method detail, figure regeneration, metric reporting, etc.
2. **Search the codebase** — look in src/, scripts/, configs/, results/, data/ for implementation evidence (see root CLAUDE.md for paths).
3. **Run a helper script** if needed — save any script in Journal/scripts/edit_NNN_*.py and run it. **ALWAYS use the conda environment `minor_proj`** (`conda run -n minor_proj python <script>`) or create it if missing. Capture output.
4. **Draft the edit** — write a complete, drop-in replacement paragraph or section in IEEE style.
5. **Save the edit** — write to Journal/edits/edit_NNN_<short_name>.md following the template in Section 6 below.
6. **Report back** — summarize what was found in the code, what was written, and any caveats or open questions.

NEVER modify the canonical PDF or LaTeX source directly without explicit instruction.

## 8. Evidence-First Paper Editing Rules

### Claim classification

Classify every manuscript statement before drafting it:

| Claim type | Minimum required evidence | Permitted wording when evidence is missing |
|---|---|---|
| Reported metric or figure | Reproducible output, exact protocol/configuration, and metric/figure artifact | `[VERIFY: run and report exact result]` |
| Evaluated capability | Checkpoint, runnable evaluation path, and recorded held-out result | "planned extension" or "unimplemented future work" |
| Integrated pipeline feature | Default or documented enabled configuration and end-to-end invocation evidence | "prototype available in the codebase" |
| Literature/novelty statement | Current primary-source verification and correct citation | Qualified statement plus `[VERIFY: literature search]` |

Do not use a source file, a CLI flag, a docstring, or a planned output path as
evidence that a result exists. Do not derive a field metric from a loss value,
or present a bound-style estimate as an exact measurement.

### Prototype versus evaluated capability

- Do not call a component “implemented” in manuscript prose merely because a
  class or script exists. State whether it was trained, evaluated, and included
  in the reported benchmark.
- The current DDPM module is an unevaluated development prototype. The default
  configuration disables it, no verified DDPM checkpoint or uncertainty-bound
  result is present, and the inference path returns optional raw turbulence
  samples without propagating them through the feature translator or LOCA
  classifier. Therefore, describe UQ as **unimplemented future work in the
  evaluated pipeline** unless the students supply reproducible contrary
  evidence.
- Keep classifier probability calibration distinct from predictive UQ. Neither
  a probability score nor turbulence samples alone establish confidence bounds
  for field reconstruction or LOCA decisions.

### Source and edit hygiene

- Treat the canonical PDF and its associated LaTeX source as read-only unless
  the user explicitly asks for a direct manuscript change. Do not assume that
  `def/`, `Paper1/`, `paper2/`, or `Paper3/` mirror the canonical version.
- For a paper request, locate the exact target paragraph in
  `Journal/paper_full_text.txt` and, where needed, the corresponding canonical
  `.tex` source before proposing wording. Quote the original confirmation
  placeholder in the edit's Context section.
- Save only the requested handoff in `Journal/edits/edit_NNN_<short_name>.md`.
  Use the next unused zero-padded numeric identifier (after Edit 012, use
  `edit_013_...`); do not renumber existing edits. Save any required helper
  script only under `Journal/scripts/edit_NNN_<short_name>.py`.
- Each edit must include exact file paths and line numbers, commands and output
  for any executed experiment, a complete drop-in replacement/addition, and
  clearly labeled caveats. Use `ready-for-review` only when the proposed text
  has all evidence needed for its claims; otherwise use `draft`.

### Experiment and reporting protocol

- Run paper-supporting Python only with
  `conda run -n minor_proj python Journal/scripts/edit_NNN_<name>.py` from the
  repository root. Capture stdout/stderr in the edit evidence and preserve the
  script, configuration, checkpoint names, dataset split, seed(s), and hardware.
- Qualify every numerical result as synthetic, Fluent-based, NPPAD-based, or
  another explicit source. Results from the synthetic mock generator cannot be
  described as validated plant or transient performance.
- For uncertainty work, report the number of samples, nominal interval level,
  interval construction, empirical coverage, interval width, calibration, and
  whether uncertainty reaches the final screening decision. Without these,
  use future-work wording rather than a UQ claim.
- Preserve the paper's strengths through precise framing, never by omitting
  material limitations or presenting unverified claims as results.
